# Дизайн: масштабирование видео до max_resolution по длинной стороне

Дата: 2026-11-23
Статус: утверждено пользователем (после ревизий: qp в конфиг; max_resolution по умолчанию 0, 1280 в примере конфига)

## Проблема

`auto-converter` конвертирует видео без изменения разрешения, уменьшая размер только завышенным QP (`constqp qp=32`). Основная экономия размера достигается понижением разрешения: видео с длинной стороной больше заданного порога нужно уменьшать до этого порога с сохранением пропорций.

## Требования

- Длинная сторона = `max(ширина, высота)` кодированного видео. Вертикальные видео (например, 1080x1920) обрабатываются автоматически: их длинная сторона — высота.
- Если длинная сторона **строго больше** `settings.max_resolution` → масштабировать пропорционально так, чтобы длинная сторона стала равна `max_resolution`. Оба размера — чётные (требование h264/nvenc). Примеры при `max_resolution: 1280`:
  - 1920x1080 → 1280x720
  - 1080x1920 → 720x1280
  - 3840x2160 → 1280x720
  - 1280x720 → без изменений (1280 не больше 1280)
- Если длинная сторона ≤ `max_resolution` — конвертация как раньше, без изменения разрешения.
- Новые ключи `config.yaml` (секция `settings`):
  - `max_resolution` — порог по длинной стороне, **по умолчанию 0** (ключ отсутствует или 0 → разрешение не проверяется и не меняется). В примере конфига (config.yaml в репо) — `1280` (720p).
  - `qp` — QP для `h264_nvenc -rc constqp`, **по умолчанию 30**. В примере конфига — `30`.
- Порог `min_file_size_mb`, аудио (aac 128k), субтитры и остальные модули не меняются.
- Конвертация не должна ломаться, если размеры видео не удалось определить: предупреждение в лог и конвертация без масштабирования.

## Изменения по файлам

### 1. `config.yaml`

В секцию `settings` добавить:

```yaml
settings:
  max_resolution: 1280
  qp: 30
```

### 2. `includes/Get-FfmpegConversionStrategy.ps1`

- Добавить необязательный параметр `-FFmpegPath` (по умолчанию `ffmpeg`). Вызывать его вместо голого `ffmpeg` (сейчас функция игнорирует путь из конфига — исправление попутной непоследовательности).
- Парсинг размеров вынести в отдельную функцию `Get-VideoDimensions` (принимает массив строк вывода `ffmpeg -i`, возвращает `@{ Width; Height }` либо `$null`): на строке видеопотока (`Stream #...: Video:`) первое совпадение `\d{2,5}x\d{2,5}`.
- `Get-FfmpegConversionStrategy` возвращает `PSCustomObject` вместо строки:
  - `DecoderCommand` — как раньше (`-c:v hevc_cuvid` / `-c:v h264_cuvid` / пустая строка);
  - `Width`, `Height` — `[int]` или `$null`, если распарсить не удалось (с предупреждением в лог).
- Отсутствие видеопотока — по-прежнему возврат `$null` (вызывающий код обрабатывает как ошибку).

### 3. `auto-converter.ps1`

- Читать конфиг: `$MaxResolution = [int]$config.settings.max_resolution` (нет ключа → 0), `$QP = [int]$config.settings.qp` (нет ключа → 30).
- Вызов стратегии: `Get-FfmpegConversionStrategy -LocalInputFile $FilePath -FFmpegPath $FFmpegPath`; декодер брать из `$strategy.DecoderCommand`; проверка `$null -eq $strategy` остаётся.
- Если `$MaxResolution -gt 0`, размеры определены и длинная сторона > `$MaxResolution`:
  - `ratio = MaxResolution / длинная сторона`;
  - `ScaleW`/`ScaleH` = округлённый до чётного `(размер * ratio)` (`[int][Math]::Round($v / 2) * 2`, допустимо смещение ≤ 1 px);
  - лог «📐 1920x1080 → 1280x720».
- Передать в `Convert-VideoWithProgress` параметры `-DecoderCommand`, `-ScaleWidth`, `-ScaleHeight`, `-QP` (при отсутствии масштабирования `ScaleWidth`/`ScaleHeight` = 0).

### 4. `includes/Convert-VideoWithProgress.ps1`

- Новые параметры: `-ScaleWidth` (по умолчанию 0), `-ScaleHeight` (0), `-QP` (30).
- `-vf`: если `ScaleWidth` и `ScaleHeight` > 0 → `scale_cuda=w=<W>:h=<H>:format=nv12`, иначе текущий `scale_cuda=format=nv12`.
- `-qp` брать из параметра вместо захардкоженного 32.

### 5. Документация

`README.md` и `README_ru.md`: описать ключи `max_resolution` и `qp` в секции Configuration и упомянуть масштабирование по длинной стороне в описании конвертации.

## Не входит в объём

- Метаданные поворота (rotation): масштабирование выполняется по кодированным размерам; если rotation-метаданные не совпадают с кодированными размерами, результат может отличаться от отображаемого разрешения. Специальной обработки нет.
- Изменение аудио, субтитров, порога `min_file_size_mb`, выбора декодера.

## Проверка

1. Парсинг: dot-source `includes/Get-FfmpegConversionStrategy.ps1`, прогнать `Get-VideoDimensions` на типовых строках вывода ffmpeg — ландшафтная (`... Video: h264 ..., yuv420p, 1920x1080, ...` → 1920x1080), вертикальная (`1080x1920`), строка без размеров (→ `$null`).
2. Чётное округление: `ratio`-расчёт на примерах выше даёт чётные 1280x720 / 720x1280.
3. Интеграционно: на копии реального 1080p-файла запустить конвертацию короткого отрезка (временно `-t 10`) с `max_resolution: 1280` → выход 1280x720; файл с длинной стороной ≤ 1280 → размеры на выходе совпадают с входом, `-vf` без w/h; `qp` из конфига присутствует в аргументах ffmpeg (строка «🚀 FFmpeg: ...» в логе).
4. Ключи отсутствуют в config.yaml → поведение без масштабирования (qp 30), ошибок чтения конфига нет.

Сборка `builder.ps1` изменений не требует (включения dot-source'ятся).
